# shellx v0.5 · Settings (Appearance-focused) — Design Spec

**Goal.** Fill the empty Settings icon on the rail with a real page whose scope is **appearance**: 3 preset themes, 3 density presets, and the Terminal's own font/size/cursor. Preferences persist to a JSON file next to `hosts.db` and take effect live.

## Scope

**In** (v0.5):
- Theme picker: 3 preset dark themes — Warm Minimal (default), Ocean, Forest.
- Density picker: Compact / Comfortable (default) / Spacious.
- Terminal font family: JetBrains Mono / SF Mono / Fira Code / Cascadia Code / Consolas (default: JetBrains Mono).
- Terminal font size: 10..20 (default 13).
- Terminal cursor style: block (default) / underline / bar.
- Reset to defaults button.
- About page (version, license, GitHub link).
- Advanced sidebar entry (dimmed, non-interactive — placeholder for v0.6+).

**Out** (deferred to later versions):
- Light-mode / colour-mode switching (all v0.5 themes are dark).
- Custom accent colour beyond the 3 preset themes.
- Custom ANSI 16-colour palette (each theme owns its palette; not user-editable).
- Numeric font-size sliders for the UI (density presets only).
- Keyboard shortcut customisation, language switching, auto-update settings.
- Terminal bell, scrollback size, word-selection rules, etc.
- Windows registry / macOS defaults / Linux config integration.

## Data model

```ts
interface Settings {
  themeId: "warm-minimal" | "ocean" | "forest";
  density: "compact" | "comfortable" | "spacious";
  terminal: {
    fontFamily: "jetbrains-mono" | "sf-mono" | "fira-code" | "cascadia-code" | "consolas";
    fontSize: number;   // clamped 10..20
    cursorStyle: "block" | "underline" | "bar";
  };
  schemaVersion: 1;
}
```

Defaults (used when the JSON file doesn't exist or fails to load):
```json
{
  "themeId": "warm-minimal",
  "density": "comfortable",
  "terminal": { "fontFamily": "jetbrains-mono", "fontSize": 13, "cursorStyle": "block" },
  "schemaVersion": 1
}
```

## Storage

**File**: `{ProjectDirs::from("", "", "shellx").config_dir()}/settings.json` — same dir as `hosts.db`.

- Windows: `%APPDATA%\shellx\config\settings.json`
- macOS: `~/Library/Application Support/shellx/settings.json`
- Linux: `~/.config/shellx/settings.json`

**Rust IPC** (2 new commands in `src-tauri/src/ipc/settings.rs`):

```rust
#[tauri::command]
pub async fn load_settings(store: State<'_, SettingsStore>) -> Result<Option<Settings>>;

#[tauri::command]
pub async fn save_settings(args: SaveSettingsArgs, store: State<'_, SettingsStore>) -> Result<()>;
```

- `load_settings` returns `None` when the file doesn't exist. Frontend then uses built-in defaults. A malformed / unreadable file also returns `None` with a stderr warning — never surfaced as a hard error (preferences are recoverable; user just gets defaults + will save fresh on next change).
- `save_settings` writes the JSON atomically: `settings.json.tmp` then rename → `settings.json`. serde_json (already in tree).

## Storage lifecycle

- App boot: `useSettingsStore.getState().load()` fires from `App.tsx`'s mount effect (before the theme/density effects that consume the loaded values).
- User change: any setter (`setTheme`, `setDensity`, `setTerminalFont*`, etc.) mutates state immediately, then schedules a **debounced save** — 300 ms after the last change, `saveSettings(currentState)`. Rapid sliding of the font-size slider won't spam the FS.
- Reset: `reset()` sets state to defaults, cancels any pending debounce, and immediately calls `saveSettings(defaults)`.

## Application mechanism

### Theme — `data-theme` on `<html>` + CSS variable overrides

`src/styles/tokens.css` extends its existing `:root` block with two override blocks:

```css
:root[data-theme="ocean"] {
  --bg: #141822;
  --panel-1: #171d2b;
  --panel-2: #1a2233;
  --accent: #4ea3ff;
  --accent-fade: rgba(78, 163, 255, 0.15);
  --accent-shadow: rgba(78, 163, 255, 0.4);
}
:root[data-theme="forest"] {
  --bg: #141a15;
  --panel-1: #171f18;
  --panel-2: #1a251c;
  --accent: #6cc57f;
  --accent-fade: rgba(108, 197, 127, 0.15);
  --accent-shadow: rgba(108, 197, 127, 0.4);
}
```

`App.tsx` (or a small `useThemeEffect` hook) has an effect that watches `settings.themeId` and does:
```ts
document.documentElement.dataset.theme = settings.themeId === "warm-minimal" ? "" : settings.themeId;
```
Empty attribute = default `:root` block, no override selector matches. No JS branching in components, no re-render — pure CSS cascade.

### Density — `data-density` on `<html>` + size variables + JS icon sizes

Extend tokens.css with density-sensitive size vars:

```css
:root {
  --font-body: 13px;
  --font-small: 12px;
  --pad-row-y: 7px;
  --pad-row-x: 12px;
}
:root[data-density="compact"] {
  --font-body: 12px;
  --font-small: 11px;
  --pad-row-y: 5px;
  --pad-row-x: 10px;
}
:root[data-density="spacious"] {
  --font-body: 14px;
  --font-small: 13px;
  --pad-row-y: 9px;
  --pad-row-x: 14px;
}
```

**Refactor** these components' hard-coded numbers to consume the vars (about 15 style-object edits total):
- `FileRow.tsx` — row `fontSize`, `padding`, gap.
- `PathBreadcrumb.tsx` — root `fontSize`.
- `LocalPathDropdown.tsx` — button + items `fontSize` / padding.
- `HostDropdown.tsx` — button + items `fontSize` / padding.
- `HostRow.tsx` — row `fontSize`.

Icons take a numeric `size` prop in lucide-react — they can't read CSS vars directly. Store exposes a selector:

```ts
export function useIconSizes() {
  return useSettingsStore((s) => {
    switch (s.density) {
      case "compact":   return { sm: 11, md: 13, lg: 15 };
      case "spacious":  return { sm: 14, md: 17, lg: 20 };
      default:          return { sm: 12, md: 15, lg: 18 };  // comfortable
    }
  });
}
```

Components that render Lucide icons switch from hard-coded `<Icon size={15} />` to `<Icon size={sz.md} />`.

`App.tsx` sets `document.documentElement.dataset.density = settings.density` in the same effect chain.

### Terminal — xterm.js `term.options` mutation on preference change

`TerminalView.tsx` currently reads xterm config from constants. Add an effect that watches `settings.terminal` and applies:

```ts
useEffect(() => {
  if (!term) return;
  term.options.fontFamily = FONT_MAP[settings.terminal.fontFamily];
  term.options.fontSize   = settings.terminal.fontSize;
  term.options.cursorStyle = settings.terminal.cursorStyle;
  fit.fit();  // character metrics changed → cols must be re-computed
}, [settings.terminal.fontFamily, settings.terminal.fontSize, settings.terminal.cursorStyle, term, fit]);
```

`FONT_MAP` constant in `src/types/settings.ts`:
```ts
export const FONT_MAP: Record<Settings["terminal"]["fontFamily"], string> = {
  "jetbrains-mono":  '"JetBrains Mono", ui-monospace, monospace',
  "sf-mono":         '"SF Mono", ui-monospace, monospace',
  "fira-code":       '"Fira Code", ui-monospace, monospace',
  "cascadia-code":   '"Cascadia Code", ui-monospace, monospace',
  "consolas":        'Consolas, ui-monospace, monospace',
};
```

`Fira Code` and `Cascadia Code` are not bundled — add `@fontsource/fira-code` and `@fontsource/cascadia-code` npm deps and import their 400 weight in `main.tsx` alongside the existing JetBrains Mono imports. Other three fonts are OS-bundled.

**Behaviour**:
- Live apply: any control's `onChange` calls the store setter → theme/density updates instantly via CSS-var cascade; terminal updates via the effect above.
- **No Save button.**
- Reset button: `confirm("Reset all settings to defaults?")` → on OK, `useSettingsStore.reset()`.
- Advanced sidebar row: fully rendered but has `opacity: 0.4`, cursor is `not-allowed`, click is a no-op. Title attribute reads "Coming in v0.6".
- About panel doesn't fetch — version comes from `import.meta.env.PACKAGE_VERSION` at build time (Vite `define`) or from a tiny `app_version` Tauri command; pick whichever avoids adding a build-time config. Since `package.json` version is trivially injectable via Vite `define`, prefer that.

## Cross-cutting

- **License MIT.** Two new npm deps: `@fontsource/fira-code`, `@fontsource/cascadia-code` — both OFL / MIT-compatible.
- **Bundle size.** Each fontsource package is ~30 KB per weight — only 400 weight imported. Total add ~60 KB to bundle. Comfortably under 15 MB target.
- **Warm Minimal palette invariant.** The theme mechanism is purely additive — default `:root` block is unchanged, so any code path that doesn't touch Settings looks identical to v0.4.3.
- **v0.2 concurrency invariant.** Rust settings handlers are synchronous FS ops; no Mutex-across-await risk.
- **v0.2 keychain rule.** Settings never touch passwords / never involve keychain.
- **Testability.** Store actions callable via `useSettingsStore.getState()` (the pattern established for `useRailFiles` in v0.4). No hook-captured actions in components.

## Testing

**Rust** (`src-tauri/src/settings/mod.rs` inline `#[cfg(test)]`):
- `load` on empty dir → `Ok(None)`.
- `save` then `load` → same struct back.
- `save` twice → second write wins (atomic replace test).
- Missing/malformed JSON file → `Ok(None)` (not an error).

**Frontend** (vitest):
- `useSettingsStore` starts with `DEFAULT_SETTINGS`.
- `setTheme("ocean")` mutates `themeId` immediately + schedules save.
- `reset()` restores defaults + immediately saves (bypasses debounce).
- `useIconSizes()` returns the correct set per density.
- `<AppearancePanel>` renders — clicking Ocean card calls store's setTheme with "ocean"; sliding size changes store; segmented cursor buttons flip cursorStyle.
- `<SettingsView>` shows Appearance by default; clicking About switches content; Advanced row is disabled (no state change on click).
- App-level: switching `railView` to `"settings"` renders `<SettingsView />` (extends existing App.test.tsx routing test).

**Manual smoke** (during v0.5 finish):
- Switch each theme → immediate colour swap + xterm palette unaffected.
- Switch each density → row heights / font sizes / icon sizes update immediately.
- Change terminal font → xterm re-renders with new font.
- Change terminal size → xterm reflows.
- Click Reset → confirm dialog → all controls back to defaults.
- Close and reopen app → settings persist.
- Open `%APPDATA%\shellx\config\settings.json` — see the JSON, edit `themeId` by hand → app picks it up on next boot.
