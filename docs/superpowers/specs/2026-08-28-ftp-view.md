# FTP / FTPS view

A rail view of its own, with its own host list and a WinSCP-style dual
pane. Browsing and transferring by hand — no polling, no auto-pull.

Motivating case: customer production lines that report data over plain
FTP. Those machines are old, they are on a factory network, and their
filenames are very likely GBK.

## Decisions

**Its own rail item, not a protocol field on saved hosts.** An FTP host
shares almost nothing with an SSH host: no key auth, no connection mode,
no terminal, no tunnels, no monitor. Folding it into `hosts` would mean a
host form that swaps out half its fields and four activity tabs that
disappear. Keeping it apart costs a second host list and a second
drawer; it buys a form and a page that are each about one thing.

**Its own table, `ftp_hosts`.** No migration on `hosts`, no branching in
any existing SSH path. The cost is that config bundle export/import
grows a second block.

**suppaftp, on `tokio` + `tokio-rustls-ring`.** Verified below.

**Never `list()` or `mlsd()`.** See Encoding.

## The client

New module `src-tauri/src/ftp/`:

- `client.rs` — one live connection: connect, auth, TLS upgrade, cwd,
  raw-byte listing, retr/stor streams.
- `listing.rs` — pure, unit-tested: parse MLSD lines, parse POSIX `LIST`
  lines, parse DOS/IIS `LIST` lines, into the same `Entry` the SFTP side
  already returns to the frontend.
- `charset.rs` — pure, unit-tested: bytes → String and String → bytes for
  `utf8` / `gbk` / `auto`.
- `manager.rs` — `FtpManager`, live connections keyed by session id, the
  same shape `SessionManager` has for SSH.

### Encoding — the one real landmine

FTP has no defined charset for filenames. A production-line box in China
is likely to speak GBK.

**suppaftp's `list()` and `mlsd()` decode the data channel with
`String::from_utf8_lossy`** (`async_ftp/tokio_ftp.rs:867`). A GBK
filename is replaced with U+FFFD before it ever reaches our code, and
that is not recoverable — the bytes are gone.

The way through: `custom_data_command()` is public and hands back the raw
`DataStream`. We issue `MLSD` / `LIST` ourselves, read bytes, and decode
with `encoding_rs`. Same on the way out: a path we send has to be encoded
back to the host's charset before it goes on the control channel.

So: a rule, not a preference. **Nothing in `ftp/` may call `list()` or
`mlsd()`.** The listing path is raw bytes, start to finish.

Per host: `auto` (try UTF-8, fall back to GBK on invalid sequences),
`utf8`, or `gbk`. `auto` is the default, and the manual lock exists
because auto will eventually guess wrong on a file whose GBK bytes
happen to be valid UTF-8.

### Listing

`MLSD` first — it has a defined grammar and gives real types and
timestamps. On `500`/`502` fall back to `LIST` and try the POSIX parser,
then the DOS one. The chosen path is remembered for the connection so
every directory does not re-probe.

Parse failures degrade per line: an unparseable line becomes an entry
with a name and no metadata, never a failed listing. A directory that
half-renders beats a directory that errors.

### Connection

Passive (PASV/EPSV) by default; an active-mode toggle for old boxes that
only do PORT. FTPS is explicit (`AUTH TLS`, port 21) by default, with
implicit (port 990) as a choice — the two cannot be told apart reliably,
so when a handshake fails the error says which one to try instead
instead of surfacing a TLS error.

Plain FTP sends the password and every byte in the clear. The form says
so under the protocol switch, and the host row and the remote pane both
carry a `plaintext` tag. It is not blocked — the factory case is real —
but nobody should have to remember it.

## IPC

`ftp_connect`, `ftp_disconnect`, `ftp_list_dir`, `ftp_mkdir`,
`ftp_rename`, `ftp_remove_file`, `ftp_remove_dir`, `ftp_download`,
`ftp_upload`, `ftp_download_dir`, `ftp_upload_dir`, plus the host CRUD
(`ftp_host_*`) mirroring `ipc/hosts.rs`.

Transfers go through the existing `TransferManager`: same queue, same
concurrency limit, same progress events, same pause / resume / cancel UI.
`resume_transfer(offset)` covers restart-at-offset; a server that refuses
`REST` reports "cannot resume" rather than silently restarting.

Passwords go to the same keychain under a `ftp:{id}` account, so nothing
about secret handling is new.

## Frontend

- `railView` gains `"ftp"`, between Files and Tunnels.
- `FtpView` — drawer (FTP hosts) + `LocalPane` | `PaneSplitter` |
  `FtpRemotePane` + `TransferStripSection`. Everything except the remote
  pane is the component that already exists.
- `FtpHostForm` — a second form, not a branch of `HostForm`.
- Reuses `state/hostSelection.ts` as-is: it is pure and keyed by id, so
  Ctrl/Shift multi-select and batch delete come along for free.
- The remote pane's path bar carries the three tags that explain nine out
  of ten FTP problems: charset, transfer mode, and plaintext-or-TLS.

## Milestones

Each one ends somewhere the app can be opened and judged.

1. **Connect and browse.** ftp module, charset, listing parsers,
   `ftp_connect` / `ftp_list_dir`, rail item, drawer, host form, remote
   pane. Plain FTP only.
2. **Move files.** Download and upload, single and directory, on the
   existing transfer queue, with resume.
3. **The rest.** mkdir / rename / delete, FTPS both modes, active mode,
   charset override, plaintext tags, config-bundle block.

## Not in scope

Polling or auto-pull on a schedule. SCP, WebDAV, S3. FTP through a
proxy. Those are separate features, and none of them is this one.

## Verified before writing this

On this Windows box, 2026-08-28, against suppaftp 10.0.2:

- Features `tokio` + `tokio-rustls-ring` exist and compile. No
  `aws-lc-rs` anywhere in the tree, so the NASM problem that pinned russh
  to `ring` does not come back.
- It resolves to `ring` 0.17.14 and `rustls` 0.23.43 — the exact versions
  shellx already builds. One crypto stack, not two.
- `custom_data_command` is public and returns the raw `DataStream`, which
  is what makes the encoding rule above possible.
- `resume_transfer(offset)`, `retr_as_stream`, `put_with_stream`,
  `append_with_stream`, `active_mode` / `set_mode`,
  `connect_secure_implicit` and `into_secure` are all present.
