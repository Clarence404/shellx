# shellx v0.4 · rail Files (Local ↔ Remote dual pane) — Design Spec

**Goal.** Give the empty **Files** icon on the activity rail a real purpose: a WinSCP-style local ↔ remote dual-pane file transfer view. Coexists with the existing per-host-tab Files (single-pane remote browser); the two serve different scenarios and neither replaces the other.

## Positioning · two Files, two jobs

| | host tab Files (v0.3, unchanged) | rail Files (v0.4, new) |
|---|---|---|
| Where | Inside each host tab, in the "Terminal ¦ Files" activity toggle | On the activity rail, independent of any tab |
| Layout | Single pane (remote only) | Two panes (left = local, right = remote) |
| Bound to | `connectionId` of the owning tab | Neither — user picks host from a dropdown in the right pane |
| Scenario | "I'm running commands and want to peek at `/etc/nginx/nginx.conf`" | "I'm here to move files, not run commands" |

## Layout — no drawer, full-width main

```
┌ rail(32) ┬────────────────── main ──────────────────────────────────┐
│  🖥       │  Local ▾  ~ Home ▾              Remote ▾  vm-local ▾     │
│  📂 ←act  │  ┌────────────── L ──┬─┬────────────── R ──────────────┐│
│  ⇋        │  │ /home/chen          │⇄│ /root                        ││
│  ⚙        │  │  📁 docs            │ │  📁 logs                     ││
│           │  │  📁 Desktop         │ │  📄 ip.log            7.4 KB││
│           │  │  📄 notes.md   1 KB │ │  📄 soft.json         543 B ││
│           │  │  …                  │ │  …                           ││
│           │  └─────────────────────┴─┴───────────────────────────────┘│
│           │  TransferQueue (shown only while transfers are live)     │
└──────────┴────────────────────────────────────────────────────────────┘
```

- **Drawer is hidden** when the Files activity is selected. `Drawer` component returns `null` for `view === "files"`; the flex row naturally reclaims the drawer's width.
- **Drawer is user-collapsible for any view.** Three triggers, all flipping a shared `drawerCollapsed` boolean in `useSessions`:
  - **Collapse button in the drawer header** — a small `PanelLeftClose` (lucide) icon at the right end of the drawer's `HOSTS` title row. This is the primary discoverable affordance.
  - Click the currently-active rail icon → toggle collapse. Clicking a *different* icon switches view and resets `drawerCollapsed` to `false`.
  - Ctrl/⌘+B → global toggle from anywhere.
  The `view === "files"` auto-hide takes precedence: the drawer is unconditionally hidden on rail Files regardless of `drawerCollapsed`.
- **Two panes** side by side, separated by a draggable splitter.
  - Left pane is always **Local** (label, not switchable — the "Local ▾" caret only picks the local path).
  - Right pane is always **Remote** (label, not switchable — the "Remote ▾" caret only picks the host).
- **Splitter** default 50/50, min 20% / max 80%, double-click resets to 50. Percent persists in `localStorage`.
- **TransferQueue** bottom strip shows **all** in-flight transfers (unfiltered) — rail Files renders `<TransferQueue />` without a `connectionId` prop, whereas the existing host-tab Files renders `<TransferQueue connectionId={activeId} />` (v0.3 behaviour, unchanged). Add a `showAll?: boolean` prop that skips the connectionId filter when true. Auto-hides when the queue drains.

## Pane structure (mirrored between panes)

Each pane is a vertical stack:

1. **Top row** (32 px)
   - Left: a small mode icon (`Folder` for local, `Server` for remote) + a single dropdown button:
     - Local pane dropdown lists: `~ Home` / `Desktop` / `Downloads` / last-visited CWD (deduped so "last" doesn't repeat a preset)
     - Remote pane dropdown lists: one row per **connected** host (with pulse-dot status, reusing host-row conventions); a final "＋ New connection" row that opens `ConnectDialog`. On successful connection, the right pane auto-selects the newly-created host and loads its home directory.
   - Right-aligned toolbar buttons: `↻` refresh, `📁+` new folder
2. **Breadcrumb row** (30 px) — reuses `PathBreadcrumb`; unchanged from v0.3
3. **File list** (fill) — reuses `FileRow`; sorted by kind (dirs first) then name
4. **Nothing else** — no per-pane transfer button; the `⇄` lives centred on the splitter

## Interactions

### Double-click
| Where | Target | Action |
|---|---|---|
| Local pane | folder | `loadDir` into the folder |
| Local pane | file | **Open in system default app** via new `local_open_in_os` IPC |
| Remote pane | folder | `loadDir` into the folder |
| Remote pane | file | **Download to the local pane's current CWD**, then TransferQueue tracks it |

### Right-click menu
| Where | Items |
|---|---|
| Local pane on file | Open, Upload to remote, Rename, Delete |
| Local pane on folder | Open, Upload to remote, Rename, Delete |
| Remote pane on file | Download to left, Rename, Delete |
| Remote pane on folder | Download to left, Rename, Delete |
| Either pane empty area | New folder, Refresh |

### Middle `⇄` transfer arrow
- Positioned centred on the splitter, above the file rows.
- **Enabled iff exactly one pane has a non-empty selection.** Direction is inferred from which pane it came from. Both-selected → disabled with a tooltip "Select on only one side". Both-empty → disabled.
- Tooltip on hover shows the previewed action: `Upload 3 items →` or `← Download 2 items`.

### Pane-to-pane drag-and-drop
- HTML5 `dragstart` on any selected row starts an internal drag; dropping on the *other* pane triggers the same transfer as `⇄` would.
- Dropping within the same pane is a no-op (drag-to-reorder is not a thing in a filesystem).
- Note: OS-to-app drops (dragging files from Explorer / Finder into the window) are already handled by host-tab Files' `onDragDropEvent`; rail Files does **not** intercept those — they still upload into whichever tab was active.

### Empty / error states
- **No host connected** (right pane): full-pane empty state — centred "Pick a host to browse remote files" and a `+ New connection` button that opens `ConnectDialog`.
- **Host was connected but socket died**: pane fades (opacity 0.5) and shows an inline banner "Connection lost — reconnect from Hosts sidebar". No auto-reconnect.
- **Remote/local error** (permission, missing): red inline banner at top of the affected pane, same style as v0.3 FileBrowserView's error banner.

## State — `useRailFiles` (new Zustand store)

```ts
{
  // left pane
  leftPath: string;            // absolute local path, "~" already resolved
  leftEntries: LocalEntry[];
  leftLoading: boolean;
  leftError: string | null;
  leftSelected: string[];      // entry names

  // right pane
  rightHost: ConnectionId | null;
  rightPath: string;           // absolute remote path
  rightEntries: SftpEntry[];
  rightLoading: boolean;
  rightError: string | null;
  rightSelected: string[];

  // splitter
  splitterPercent: number;     // 20..80, default 50

  // actions
  setLeftPath(p): void
  setRightHost(id): void
  setRightPath(p): void
  loadLeft(): Promise<void>
  loadRight(): Promise<void>
  selectLeft(name, multi): void
  selectRight(name, multi): void
  clearSelectionLeft(): void
  clearSelectionRight(): void
  transfer(direction: 'up' | 'down'): void  // fires sftp_upload / sftp_download for the selection
  setSplitter(pct): void
}
```

### Persistence (`localStorage`)
- `railFiles.leftPath` — last local CWD
- `railFiles.rightHost` — last-used host id
- `railFiles.rightPath.<hostId>` — last remote CWD **per host**
- `railFiles.splitterPercent`

## New Rust IPC — local filesystem

All accept/return the same JSON shape as their `sftp_*` cousins so the frontend `LocalEntry` and `SftpEntry` types stay near-identical.

| Command | Args | Returns | Notes |
|---|---|---|---|
| `local_list_dir` | `{ path }` | `LocalEntry[]` | `std::fs::read_dir` + `metadata` |
| `local_realpath` | `{ path }` | `String` | `std::path::PathBuf::canonicalize`; handles `~` up front via `dirs::home_dir` |
| `local_default_roots` | — | `{ home, desktop, downloads }` | Uses `dirs` crate |
| `local_mkdir` | `{ path }` | `()` | `std::fs::create_dir` |
| `local_rename` | `{ from, to }` | `()` | `std::fs::rename` |
| `local_remove_file` | `{ path }` | `()` | `std::fs::remove_file` |
| `local_remove_dir` | `{ path }` | `()` | `std::fs::remove_dir_all` (be explicit in confirm dialog) |
| `local_open_in_os` | `{ path }` | `()` | Cross-platform via `std::process::Command`: Windows `explorer.exe`, macOS `open`, Linux `xdg-open` |

Add `dirs = "5"` to `Cargo.toml`. No new Tauri plugin needed.

## Reused IPC (unchanged)
- `sftp_list_dir` / `sftp_realpath` / `sftp_mkdir` / `sftp_rename` / `sftp_remove_file` / `sftp_remove_dir`
- `sftp_upload(conn_id, local, remote)` / `sftp_download(conn_id, remote, local)`
- `transfer_list()` / `transfer_cancel(id)` (frontend already listens for `transfer:started/progress/done`)

## New UI components

Each is small; nothing exceeds 200 lines.

- `RailFilesView.tsx` — main container. Reads `useRailFiles`. Renders `LocalPane`, `PaneSplitter`, `RemotePane`, and `TransferQueue` (existing, but rendered globally not per-connection).
- `LocalPane.tsx` — left pane. Composes `LocalPathDropdown`, `PathBreadcrumb`, `FileRow` list. Hosts double-click, drag events, right-click menu.
- `RemotePane.tsx` — right pane. Same shape as LocalPane but talks to `sftp_*`. Handles the "no host" empty state.
- `PaneSplitter.tsx` — pure DOM/CSS resizer. Mousedown → capture pointer → mousemove updates splitter %. Double-click resets to 50. Uses standard `col-resize` cursor.
- `TransferArrow.tsx` — `⇄` button that sits over the splitter. Reads selection state and picks direction.
- `LocalPathDropdown.tsx` — dropdown listing Home / Desktop / Downloads / last-visited (deduped so "last" doesn't duplicate a preset).
- `HostDropdown.tsx` — dropdown listing connected hosts (from `useSessions`), plus a "＋ New connection" row that opens `ConnectDialog`.

## Reused components
- `FileRow`, `PathBreadcrumb`, `HostContextMenu`, `TransferQueue`, `ConnectDialog` — no changes to their public API.
- `Drawer` — extends to `if (view === "files" || drawerCollapsed) return null;` and reads `drawerCollapsed` from `useSessions`. Its header row gets a right-aligned `PanelLeftClose` icon button that calls `toggleDrawer()`.
- `ActivityRail` — clicking the icon whose id matches the current view toggles `drawerCollapsed`; clicking a different id switches view and force-sets `drawerCollapsed` to `false`.
- Global keybinding handler in `App.tsx` adds Ctrl/⌘+B → `useSessions.toggleDrawer()`.

## Testing

### Rust (unit tests using `tempfile::TempDir`)
- `local_list_dir` returns entries with correct kind/size/permissions
- `local_realpath` expands `~` and resolves `..`
- `local_default_roots` returns non-empty paths on the current platform
- `local_mkdir` / `local_rename` / `local_remove_file` / `local_remove_dir` happy paths + one error path each
- `local_open_in_os` is a smoke test only (spawn returns Ok on a temp file — we can't assert what the OS does)

### Frontend (vitest)
- `RailFilesView`: renders remote empty state when `useSessions.sessions` is empty
- `RailFilesView`: switching the right-pane host dropdown updates `rightHost` + triggers `loadRight`
- `LocalPane`: double-click a file calls `local_open_in_os`, does **not** trigger a transfer
- `RemotePane`: double-click a file calls `sftp_download` with `leftPath` as destination
- `TransferArrow`: enabled/disabled matches the selection matrix (0/0 off, 1/0 on, 0/1 on, 1/1 off)
- `PaneSplitter`: mousedown+move updates state; double-click resets to 50
- `useRailFiles`: `transfer('up')` correctly wraps `sftp_upload` per selected item

## Out of scope for v0.4 (explicitly not built)

The following were considered and deferred:

- Hidden-file filter (`.` prefix toggle)
- Upload-conflict dialog beyond a browser `confirm()` — default remains "overwrite"
- Custom local bookmarks beyond the three preset roots (would need new SQLite table)
- Resume interrupted transfers — needs transfer persistence + `russh-sftp` seek support verification
- Remote ↔ Remote direct transfer between two hosts — either needs local staging (slow, disk-heavy) or A→B direct connection (not realistic)

## Cross-cutting concerns

- **Warm Minimal palette**: no new colors — reuse `--accent`, `--panel-1/2`, `--text-1/2/3`, `--border`, `--border-hi`. Font: `--font-mono` for file names (matches v0.4 host-tab Files change).
- **Concurrency invariants (from v0.2)**: any `.await` inside the new Rust IPC handlers must not hold a `MutexGuard`. Local FS calls are synchronous — wrap in `tokio::task::spawn_blocking` if they turn out to be slow enough to block the async runtime (probably not for `read_dir` on typical dirs).
- **Bundle size**: `dirs` crate adds ~0 KB (tiny). `std::process::Command` is stdlib. No new npm deps. Bundle should stay well under 15 MB.
- **Cross-platform**: `local_open_in_os` needs platform-specific `Command` invocation; tested manually on Windows first, Linux/macOS at CI time (release workflow already builds both).

## Estimated effort

Roughly 1-2 development days end-to-end for a solo run, or ~4-6 subagent-driven tasks (~1 day) using the SDD flow you've been using for v0.1/v0.2/v0.3.

Tasks would decompose along the lines of:
1. Rust: `local_*` IPC + tests
2. Frontend: `useRailFiles` store + `RailFilesView` skeleton
3. Frontend: `LocalPane` + `LocalPathDropdown`
4. Frontend: `RemotePane` + `HostDropdown`
5. Frontend: `PaneSplitter` + `TransferArrow` + drag-drop wiring
6. Frontend: Drawer hide-on-files + polish + tests

That decomposition is for the implementation plan, not this design spec.
