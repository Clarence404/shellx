# v0.9 SSH Tunnels — Design Spec

Date: 2026-08-10  
Status: Approved

## Overview

Add local-forward SSH tunnel support to shellx. Users configure tunnel rules per host and choose a connection mode. Tunnels are established automatically on connect and can be toggled live within a session.

---

## Scope (B)

**In scope:**
- Connection mode selector per host (Term+Tunnels / Tunnels-only / Terminal-only)
- Port forwarding rules stored in DB per host
- Tunnels tab in the session content area
- Live per-rule toggle (immediate effect)
- Session-only (unsaved) tunnel rules added in-session
- Tab bar adapts based on connection mode

**Out of scope (future):**
- Remote forwarding (only local forward in v0.9)
- Global Tunnels rail view / badge count
- Environment badges and PROD confirmation dialog
- HTTP "Open in browser" action
- Per-tunnel auto-reconnect logic beyond the existing SSH reconnect path

---

## HostForm Changes

### Tab layout

The HostForm gains a two-tab layout:

- **基本 tab** — existing fields unchanged: Label, Host, Port, Username, Auth (key/password)
- **Tunnels tab** — new: Connection mode + Port forwarding rules

Cancel/Save buttons are shared across both tabs and save the complete form state.

### Connection mode (Tunnels tab)

A three-segment selector:

| Option | Behavior |
|--------|----------|
| 仅 Terminal | Shell only, no tunnels. Equivalent to v0.8 behavior. Tunnel rules section is rendered but greyed out. **Default for new hosts.** |
| Term + Tunnels | Opens a shell channel and establishes all enabled tunnel rules. |
| 仅 Tunnels | No shell channel opened. Tunnels only. Session content area shows only the Tunnels tab. Intended for jump hosts with `ForceCommand` that disallow interactive login. |

Stored as `connection_mode TEXT` on the `hosts` table. Values: `"terminal_only"` (default) | `"term_tunnels"` | `"tunnels_only"`.

### Port forwarding rules (Tunnels tab)

A list of saved tunnel rules for this host. Each row:

```
● DB prod     15432 → db.internal:5432    ×
● Redis       16379 → cache.internal:6379  ×
○ Kibana      15601 → kibana.internal:5601 ×
```

- Filled dot = enabled (will auto-start on connect)
- Empty dot = disabled (rule is saved but won't start on connect)
- `×` deletes the rule

**Add rule — inline row:** Clicking `+ Add` expands an input row at the bottom of the list:

```
[Label     ] [Local port] [Remote host:port          ] [✓]
```

Pressing ✓ (or Enter) appends the rule. Pressing Escape cancels. No popover.

## Database Schema

### New `tunnels` table

```sql
CREATE TABLE IF NOT EXISTS tunnels (
  id          TEXT PRIMARY KEY NOT NULL,
  host_id     TEXT NOT NULL REFERENCES hosts(id) ON DELETE CASCADE,
  label       TEXT NOT NULL DEFAULT '',
  local_port  INTEGER NOT NULL,
  remote_host TEXT NOT NULL,
  remote_port INTEGER NOT NULL,
  enabled     INTEGER NOT NULL DEFAULT 1,   -- 0 = disabled, 1 = enabled
  sort_order  INTEGER NOT NULL DEFAULT 0,
  created_at  INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_tunnels_host_id ON tunnels(host_id);
```

### Migration on `hosts` table

```sql
ALTER TABLE hosts ADD COLUMN connection_mode TEXT NOT NULL DEFAULT 'terminal_only';
```

Added via the same idempotent `has_column` migration guard used for `auth_method` / `key_path` in v0.8.

## Rust Backend

### `TunnelRule` struct (`store/tunnels.rs`)

```rust
pub struct TunnelRule {
    pub id: Uuid,
    pub host_id: Uuid,
    pub label: String,
    pub local_port: u16,
    pub remote_host: String,
    pub remote_port: u16,
    pub enabled: bool,
    pub sort_order: i32,
}
```

CRUD via `TunnelStore`: `list_for_host`, `insert`, `update`, `delete`.

### `TunnelHandle` (`session/manager.rs`)

Each active tunnel is a `tokio::task::JoinHandle` that:
1. Binds `TcpListener` on `127.0.0.1:<local_port>`
2. For each accepted TCP connection, calls `handle.channel_open_direct_tcpip(remote_host, remote_port, "127.0.0.1", local_port)` on the russh `Handle`
3. Splices bytes bidirectionally between the TCP socket and the SSH channel

`LiveConnection` gains a `tunnels: HashMap<Uuid, TunnelHandle>` field where `Uuid` is the rule ID (or a generated ID for session-only rules).

### Connection mode handling (`ipc/mod.rs`)

`open_connection` accepts `connection_mode` and:
- `term_tunnels` → open shell + start all enabled rules
- `tunnels_only` → skip `open_shell`, start all enabled rules
- `terminal_only` → open shell, do not start any tunnels

### IPC commands (new file `ipc/tunnels.rs`)

| Command | Args | Returns |
|---------|------|---------|
| `tunnel_list_for_host` | `host_id: Uuid` | `Vec<TunnelRule>` |
| `tunnel_add` | `NewTunnelRule` | `TunnelRule` |
| `tunnel_update` | `UpdateTunnelRule` | `TunnelRule` |
| `tunnel_delete` | `id: Uuid` | `()` |
| `tunnel_open` | `session_id: Uuid, rule_id: Uuid` | `()` |
| `tunnel_close` | `session_id: Uuid, rule_id: Uuid` | `()` |
| `tunnel_add_session` | `session_id: Uuid, NewTunnelRule` | `TunnelStatus` |

### Event: `tunnel:status`

```typescript
{ session_id: string, rule_id: string, status: "active" | "error" | "closed", error?: string }
```

Emitted whenever a tunnel's status changes (bind error, SSH channel close, etc.).

## Frontend

### Types (`src/types/tunnel.ts`)

```typescript
export interface TunnelRule {
  id: string;
  host_id: string;
  label: string;
  local_port: number;
  remote_host: string;
  remote_port: number;
  enabled: boolean;
  sort_order: number;
}

export interface TunnelStatus {
  rule_id: string;
  session_id: string;
  status: "active" | "error" | "closed";
  error?: string;
  session_only?: boolean;  // true = not persisted, disappears on disconnect
}
```

### State (`src/state/sessions.ts`)

- `ActivityKind` extended: `"terminal" | "files" | "tunnel"`
- `tunnelStatuses: Record<ConnectionId, TunnelStatus[]>` added to store
- `setTunnelStatus(sessionId, status)` action
- On `connection:closed` event, clear `tunnelStatuses[id]`

### HostForm (`src/components/HostForm.tsx`)

- Tabbed layout: `activeTab: "basic" | "tunnels"` local state
- Tab bar renders above the scrollable body
- Tunnels tab: connection mode segment + rules list + inline add row
- `connection_mode` included in `SaveHostArgs` / `UpdateHostArgs`
- `tunnel_rules` changes applied via separate IPC calls on Save (add/delete individually)

### Tab bar in session (`src/components/TabBar.tsx` or equivalent)

Tab bar adapts based on `host.connection_mode`:

```typescript
const tabs = connectionMode === "tunnels_only"
  ? ["tunnel"]
  : connectionMode === "term_tunnels"
    ? ["terminal", "files", "tunnel"]
    : ["terminal", "files"];  // terminal_only default
```

On connect, `activeActivity` is set to `"tunnel"` if mode is `tunnels_only`, otherwise `"terminal"`. Default mode for new hosts: `terminal_only` (v0.8 behavior unchanged out of the box).

### `TunnelsPanel` (`src/components/TunnelsPanel.tsx`)

Shown when `activeActivity === "tunnel"`. Layout:

```
[header: "N rules · M active"          + Add]
[● DB prod   localhost:15432 → db:5432  toggle]
[● Redis     localhost:16379 → ...      toggle]
[○ Grafana   localhost:13000 → ...  SESSION  toggle]  ← session-only
[──────────────────────────────────────────────]
[+ Add tunnel for this session]
```

- **Toggle (persisted rules):** calls `tunnel_open` / `tunnel_close` IPC for the live tunnel effect, AND calls `tunnel_update` to flip `enabled` in DB so the preference is remembered for the next connection.
- **Toggle (session-only rules):** calls `tunnel_open` / `tunnel_close` only; no DB write.
- **"Add tunnel for this session":** opens an inline form; on confirm calls `tunnel_add_session`; the command opens the tunnel immediately (no DB write) and returns a `TunnelStatus` with `session_only: true`. The rule is tracked in `tunnelStatuses` only and disappears on disconnect.
- Session-only rules are **not** `TunnelRule` objects (no `id`/`host_id`). The frontend identifies them by a locally-generated ephemeral ID stored in `TunnelStatus`.
- SESSION badge: `background: var(--accent-fade); color: var(--accent); font-size: 10px`
- Status dot: green = `active`, grey = `closed`/disabled, amber = `error`

## Error Handling

| Scenario | Behavior |
|----------|----------|
| Local port already in use | `tunnel:status` → `error`; dot turns amber; tooltip shows "Port 15432 in use" |
| SSH channel rejected by server | Same as above |
| SSH connection drops | All tunnels move to `closed`; reconnect handled by existing session reconnect logic; tunnels re-established after reconnect |
| Rule deleted while tunnel is active | Close the tunnel, then delete from DB |

---

## Out-of-scope Notes

The following are noted here to avoid scope creep during implementation:

- Remote port forwarding (`-R` style): russh supports `tcpip_forward` but the UX for it is different (server binds, not client). Defer.
- Dynamic (SOCKS) forwarding: not in scope.
- IPv6 bind addresses: default to `127.0.0.1` only for now.
