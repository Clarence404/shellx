**日期**：2026-08-04
**状态**：Draft — 待用户确认
**作者**：Chen Han

## 1. 概述

v0.3 让 shellx 从"SSH 终端 + 主机管理器"升级为"SSH + SFTP 双活动客户端"。核心变化是 **Protocol 抽象**（v0.2 承诺的 trait 抽取兑现）+ **一连接多活动**（一个 SSH 连接同时承载 Terminal + Files），配套一批 v0.2 遗留的 UX polish。

**一句话定位**：*"打开一台机器，既能敲命令也能拖文件——一次登录，两种活动。"*

**不做**（推 v0.4+）：SSH 公钥认证、host-key 验证、凭据双轨、代码签名、FTP/FTPS、文件预览/编辑。

## 3. 数据模型（无变化）

v0.2 的 `hosts.db` schema 和 keychain 存储都不动。SFTP 不需要额外持久化字段——共享现有 host 记录（label / host / port / username / password）。

未来的传输历史（v0.5+）可以加 `transfers` 表，但 v0.3 传输队列纯内存态。

## 4. Rust 架构：Protocol trait 抽取 + Connection/Activity 分层

### 4.1 现状（v0.2）与问题

v0.2 的 `SshSession { handle, channel }` 把"一个 SSH 连接"和"一个 shell channel"绑定成一个类型，无法在同一连接上再开 SFTP subsystem。`SessionManager::open_ssh` 也是"一个 SessionId = 一个 channel"。

### 4.2 v0.3 抽象

**`src-tauri/src/protocol/mod.rs`** 新增 traits：

```rust
#[async_trait]
pub trait Connection: Send {
    async fn open_shell(&mut self) -> Result<ShellHandle>;
    async fn open_sftp(&mut self) -> Result<SftpHandle>;
    async fn disconnect(&mut self) -> Result<()>;
}
```

**`src-tauri/src/protocol/ssh.rs`** 重构：

- `SshProtocol::connect(host, port, auth) -> Result<SshConnection>`（返回类型变了，之前是 `SshSession`）
- `SshConnection { handle: russh::client::Handle }` 实现 `Connection` trait
- `open_shell` 内部走 v0.2 那套 `channel_open_session` + `request_pty` + `request_shell`，包装成 `ShellHandle`
- `open_sftp` 内部走 `handle.channel_open_session().await` + `channel.request_subsystem("sftp")` + `russh_sftp::client::SftpSession::new(channel.into_stream())`，包装成 `SftpHandle`

**`ShellHandle`** 接口跟 v0.2 `SshSession` 一致（write_input / read_output / resize / close）——这样上层 `SessionManager` 的 driver_loop 逻辑几乎不变。

**`SftpHandle`** 接口：

```rust
pub struct SftpHandle { inner: russh_sftp::client::SftpSession }

#[derive(Debug, Clone, Serialize)]
pub struct Entry {
    pub name: String,
    pub kind: EntryKind,     // Directory | File | Symlink | Other
    pub size: u64,
    pub modified: Option<i64>, // unix ms
    pub permissions: u32,       // POSIX mode
}

impl SftpHandle {
    pub async fn list_dir(&self, path: &str) -> Result<Vec<Entry>>;
    pub async fn stat(&self, path: &str) -> Result<Entry>;
    pub async fn read_file(&self, path: &str) -> Result<Vec<u8>>;
    pub async fn write_file(&self, path: &str, data: &[u8]) -> Result<()>;
    pub async fn rename(&self, from: &str, to: &str) -> Result<()>;
    pub async fn remove_file(&self, path: &str) -> Result<()>;
    pub async fn remove_dir(&self, path: &str) -> Result<()>;
    pub async fn mkdir(&self, path: &str) -> Result<()>;
    // 大文件用流式：
    pub async fn open_read_stream(&self, path: &str) -> Result<impl AsyncRead>;
    pub async fn open_write_stream(&self, path: &str) -> Result<impl AsyncWrite>;
    pub async fn close(&mut self) -> Result<()>;
}
```

### 4.3 SessionManager 重构

**`src-tauri/src/session/manager.rs`**：

- `SessionInfo` → `ConnectionInfo { id, label, kind, host_id, activities: ActivitiesState }`（新字段 `activities` 追踪已打开哪些 channel）
- `SessionKind::Ssh` → `ConnectionKind::Ssh`
- Map: `Arc<Mutex<HashMap<ConnectionId, LiveConnection>>>` 每个 LiveConnection 内含：
  ```rust
  struct LiveConnection {
      info: ConnectionInfo,
      conn: Box<dyn Connection>,
      shell: Option<LiveShell>,        // 首次 open_shell 后填
      sftp: Option<LiveSftp>,          // 首次 open_sftp 后填
      shell_writer: Option<mpsc::Sender<ShellCmd>>,  // driver_loop 输入通道
      shell_subs: Option<mpsc::Sender<Vec<u8>>>,     // 订阅者
  }
  ```
- 单个 driver_loop 只驱动 shell channel 的读写（跟 v0.2 一样），SFTP 是请求-响应模型，不需要 driver_loop
- `close_connection` → 依次 close_shell、close_sftp、disconnect

### 4.4 传输任务模型

**`src-tauri/src/transfer/mod.rs`**（新模块）：

```rust
pub type TransferId = uuid::Uuid;

#[derive(Debug, Clone, Serialize)]
pub struct TransferInfo {
    pub id: TransferId,
    pub connection_id: ConnectionId,
    pub direction: Direction,     // Upload | Download
    pub local_path: String,
    pub remote_path: String,
    pub total_bytes: u64,
    pub bytes_done: u64,
    pub state: TransferState,     // Queued | Active | Done | Failed(String) | Cancelled
    pub started_at: i64,
}

pub struct TransferManager {
    tasks: Arc<Mutex<HashMap<TransferId, LiveTransfer>>>,
    // active per-connection: limits concurrent transfers to 1/connection (v0.3 keeps it simple)
}
```

每个 transfer 是一个 `tokio::spawn` 的任务，持有一个 `oneshot::Receiver` 作为取消信号；每处理 64 KB chunk 通过 Tauri event 发一次 `transfer:progress`。

### 5.2 FileBrowserView 组件

```

└────────────────────────────────────────────┘
```

**顶部工具栏**：
- 面包屑路径：`~ / apps / deploy` — 每一段是可点击的（跳到该目录）
- 刷新按钮 `⟳`：重新拉当前目录
- 上传按钮 `＋ Upload`：打开系统文件选择器（`@tauri-apps/plugin-dialog` 的 `open({multiple: true})`）

**文件列表**：
- `..` 行（当 cwd 不是根时显示）
- 目录：紫色 Folder 图标（Lucide `Folder`），点击进入
- 文件：灰色 File 图标（Lucide `File`），双击 = 下载到系统 Downloads 文件夹（`@tauri-apps/plugin-fs` 拼路径），右键弹菜单
- 右键菜单（复用 v0.2 `HostContextMenu`）：**Download to...**（打开保存对话框）、**Rename**（inline rename input）、**New folder**（弹小对话框）、**Delete**（确认后调用 `sftp_remove_*`）
- 选中多行：Ctrl/Shift-click 多选，Delete 键批量删除（带二次确认）
- 排序：默认目录在前，同类型按名字字母序（v0.3 不做用户可选排序）

**拖拽上传**：
- **不用 HTML5 `onDrop`**（Web `File.path` 不是标准属性）——用 Tauri 2 的原生拖放：`getCurrentWebviewWindow().onDragDropEvent(event => ...)` 来自 `@tauri-apps/api/webviewWindow`
- Tauri 会把用户从 OS Explorer 拖进窗口的文件路径以原生字符串形式回调过来（含 `event.payload.paths: string[]`）
- FileBrowserView 只在自己 mount 时订阅这个事件，unmount 时 unsubscribe，避免全窗口范围内误触发
- 拿到路径数组后，每个路径启动一个 `sftp_upload` transfer，进度事件流回 UI

**传输队列条**（底部）：
- **默认隐藏**（仅当 `activeTransfers.length > 0` 时渲染）
- 每条 transfer 一行：direction 箭头（↑↓）+ 文件名 + progress bar + `bytes_done / total` + `✕` 取消按钮
- 传输完成后行淡出并保留 5 秒，然后从列表移除；5 秒内所有 transfer 都完成 → 整个条淡出隐藏
- 失败的行显示红色错误短信 + 保留 10 秒供用户看到

### 5.3 TerminalView（几乎不变）

跟 v0.2 一样，只是订阅事件时用 `ConnectionId` 而不是老的 `SessionId`（其实底层就是同一个 UUID，只是命名变了）。

### 5.4 空状态和 Drawer（不变）

v0.2 的空状态 + drawer + ⌘K palette 全部保持。saved-host click flow 仍走 `handleConnectSavedHost` → 建 connection → 默认打开 Terminal activity。

## 6. C 精选 4 项落地

### 6.1 Dead-tab 淡出消失

- Rust 端：`connection:closed` 事件已存在（v0.1 driver_loop 自然退出时发的 `session:closed` 换名 + 扩展），SFTP channel 也在 disconnect 时发一次
- Frontend：App.tsx 的 `onSessionClosed` 现在改成"标记 `session.state = 'closed'` + 加 CSS animation → 300ms 后调 `removeSession(id)`"
- CSS：session state 'closed' 的 tab 显示 `opacity: 0.4` + `filter: grayscale(0.6)` + `pointer-events: none`；同时 300ms transition
- 用户还是能在这 300ms 内看到"这台机器断了"，然后 tab 自动消失，不留视觉噪声

### 6.2 Ctrl+W/T 让位给 shell readline

- `useTabHotkeys` 重写：Windows/Linux 上 `Ctrl+T`/`Ctrl+W` 不再拦截，`Ctrl+Shift+T`/`Ctrl+Shift+W` 分别新建/关闭 tab；`Ctrl+Tab`/`Ctrl+Shift+Tab` 切换 tab 不变
- macOS 上保持 `Cmd+T`/`Cmd+W`（无冲突，Cmd 系已是应用级习惯）
- README 里更新快捷键说明

### 6.3 HostForm edit 模式加 "Forget stored password"

- HostForm.tsx：edit 模式加一个复选框（default unchecked）"Forget stored password"，仅在 `keychainAvailable && initial 有密码` 时显示
- 勾选后提交，password 字段发 `null`（v0.2 update_host 已支持 `Some(None) → 删 keychain`）
- 提示语：checkbox 下方灰字 "This will remove the saved password. You'll need to type it next connection."

### 6.4 HostRow 键盘可达

- `HostRow.tsx`：把内嵌 `<span onClick={handleMoreClick}>` 改成独立 `<button>` 兄弟节点
- 加 `tabIndex={0}`、`role="button"`、`aria-label="host options"`、`onKeyDown` 处理 `Enter`/`Space`
- 视觉上还是 hover 显示（用 CSS `:has(:hover)` 或 grouped state 让父 row hover 也让 button 可见）
- 新增 vitest 用例：Tab 键能聚焦到 ⋯ button；Enter 触发弹菜单

## 8. 数据流与 IPC

**新增 Tauri commands**：

```
open_connection(args: OpenConnArgs) -> ConnectionInfo
close_connection(args: { id: ConnectionId })
open_shell(args: { conn_id: ConnectionId })
open_sftp(args: { conn_id: ConnectionId })
sftp_list_dir(args: { conn_id, path }) -> Vec<Entry>
sftp_download(args: { conn_id, remote_path, local_path }) -> TransferId
sftp_upload(args: { conn_id, local_path, remote_path }) -> TransferId
sftp_rename(args: { conn_id, from, to })
sftp_remove_file(args: { conn_id, path })
sftp_remove_dir(args: { conn_id, path })
sftp_mkdir(args: { conn_id, path })
transfer_list() -> Vec<TransferInfo>
transfer_cancel(args: { transfer_id })
```

**v0.2 兼容命名**：
- `open_ssh_session` → **重命名为 `open_connection`**（保留原参数）
- `close_session` → **`close_connection`**
- `write_session_input` / `resize_session` / `list_sessions` **保留原名**（这些都是 shell channel 层面的操作，不受影响）

**新增事件**：
- `connection:closed` — 底层 SSH 断开
- `transfer:progress` — `{ transfer_id, bytes_done, total_bytes, rate_bps }`，每 100ms 或每 64KB 发一次
- `transfer:done` — `{ transfer_id, state: "done" | "failed" | "cancelled", error?: string }`
- 沿用：`session:data`（现指 shell channel 数据）

**Tri-state SessionInfo → ConnectionInfo**：TypeScript 侧改名，字段 `state: "active" | "closed"` 新增。

## 12. Migration & 兼容

- **v0.2 → v0.3 用户数据**：hosts.db schema 不变；keychain 不变；saved hosts + passwords 全部继续可用

## 13. 里程碑与验收

**v0.3.0 验收标准**：

1. 首次启动，saved host 双击打开 → 默认 Terminal activity，一切照旧
2. 点顶部 Files pill → SFTP subsystem 打开、拉当前目录、渲染文件列表 <1s
3. 拖 3 个文件到 Files 视图 → 传输队列出现，进度实时更新，全部完成后 5s 淡出
4. 右键文件 → Rename / Delete / Download to... 全部功能可用
5. 右键空白 → New folder 弹小对话框 → 立即出现在列表
6. Ctrl+Shift+T 新建 tab、Ctrl+Shift+W 关闭当前 tab（不再抢终端的 Ctrl+W/T）
7. 断开 SSH 连接 → tab 淡出 300ms 后消失
8. HostForm edit → "Forget stored password" 勾选 + Save → keychain 里对应条目删除
9. Tab 键能聚焦到 HostRow 的 ⋯ 按钮，Enter 弹菜单
10. `cargo test --lib` ≥ 20；`cargo test --features test-fixtures` 通过；`pnpm test -- --run` ≥ 30
