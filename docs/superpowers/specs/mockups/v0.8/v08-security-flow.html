🔑

首次连接这台服务器

shellx 之前没见过 test-bastion.company.com，请核对下面的指纹是否与服务器管理员告知的一致。
主机test-bastion.company.com:22
密钥类型ED25519
指纹SHA256:HbW3g8vpcJXm3JgqXhI2R6ZKvJqVrHqOxwFrxRwXXXX
信任后指纹将写入 ~/.ssh/known_hosts，命令行 ssh 也会认。
点 信任并保存 → 指纹追加进 ~/.ssh/known_hosts → 继续认证。之后连这台服务器永远不再弹（走左边绿色分支静默通过）。你在命令行接受过的服务器，shellx 也直接静默通过——两边互通
② 指纹变化 · 中间人警告
⚠

服务器指纹变了！

prod-bastion.company.com 返回的指纹与 known_hosts 中保存的不一致。这可能是中间人攻击。
已保存SHA256:HbW3g8vpcJXm3JgqXhI2R6ZK…
现在收到SHA256:Zk9mQwErTyUiOpAsDfGhJkL2…
如果服务器最近没有重装或更换密钥，请立即取消并联系管理员。
默认按钮是"取消连接"（右侧、红色、粗体）。要继续必须点左边的弱化按钮，点了之后还会追加新指纹到 known_hosts。这个对话框设计原则：让"离开"比"继续"更容易
公钥认证怎么配（一次性）
编辑主机表单里加一个"认证方式"段。你那台 test-bastion 的配法：
③ 主机表单 · 认证方式段
认证方式
🔑 密钥文件
🔒 密码
私钥文件
C:\Users\ChenHan\.ssh\id_ed25519
自动发现：shellx 扫描 ~/.ssh/ 找到了 id_ed25519 · id_rsa，点击直接选用
Passphrase（如果密钥有）
••••••••••
存入 Windows 凭据管理器（OS keychain），只需输入这一次。没有 passphrase 就留空
切到"密钥文件"模式 → 从自动发现列表点 id_ed25519（或手动浏览）→ 输一次 passphrase（存 keychain）→ 保存。之后每次连接全自动，什么都不用输
④ 日常连接 · 零输入
配好之后，日常点击 test-bastion 的完整体验：
1. 点击主机（或 + 菜单 quick connect）
2. 指纹静默校验通过（known_hosts 有记录）
3. 密钥自动解锁（passphrase 从 keychain 取）
4. 终端出现 chen.han@test-bastion:~$
从点击到连上 1-2 秒，全程零弹窗零输入。弹窗只出现在两种情况：新服务器（一台一次）· 指纹变化（罕见+应该警惕）
总结 · 和现在的区别
维度 现状 v0.7.1 v0.8 之后
服务器身份验证 无 · 无条件信任任何服务器 TOFU · 指纹存 ~/.ssh/known_hosts · 变化即大红警告
中间人攻击 完全无感知，密码直接被截 第二次起连接即可发现（指纹不匹配）
认证方式 仅密码 公钥（Ed25519/RSA + passphrase 走 keychain）+ 密码
与命令行 ssh 的关系 互不相干 共用 known_hosts（只追加）· 一处信任两边通用
你那条 ssh -i 命令 shellx 替代不了（没有 -i） -i 部分完全替代（-L 部分等 v0.9）
日常连接体验 点击 → 连上（但不安全） 点击 → 连上（同样零输入，且安全）· 仅新服务器多一次确认
