# Host groups and sidebar search

Status: approved 2026-10-12, implemented on `feat/host-groups`. Targets v0.35.0
(the date and version in this file's name match the mockup's, so the two sort
and compare together).
Mockup: [`docs/mockups/2026-10-12-v0.35-host-groups-and-search.html`](../../mockups/2026-10-12-v0.35-host-groups-and-search.html) — open in a
browser; it is a clickable prototype with fake data and is the canonical visual
reference (sidebar, new-connection form, batch move, search).

The saved-hosts list is one flat column ordered by when each host was added.
Past a dozen machines it stops being scannable: nothing says which are
production and which are test, and finding one means scrolling. This adds
**groups** to organise the list and a **search box** to cut through it.

## Decisions

**One group per host — no tags.** Each host belongs to at most one group
(`prod`, `test`, `home`). Tags (many per host) were considered and left out:
they need their own editing UI, a filter model, and a rule for how they render
in a list that is inherently one-dimensional. Groups cover the real use,
"which environment is this", with a fraction of the surface. Revisit tags only
if groups prove too coarse.

**Groups are derived, not stored.** A single nullable column
`hosts.group_name`. There is no `groups` table: a group exists exactly while at
least one host names it, and disappears when the last member leaves. That keeps
the migration to one `ALTER TABLE`, makes "rename" and "dissolve" plain updates
over member hosts, and leaves nothing to get out of sync. The accepted cost is
that an empty group cannot be created ahead of time — you create it by moving a
host into it.

**No nesting.** Folders inside folders would turn the sidebar into a tree
control with its own keyboard and selection semantics. One level only.

**No drag-and-drop into a group.** Considered and rejected for now: three
other routes already exist (below), and HTML5 drag inside the Tauri window is
costly to make reliable. Right-click, Ctrl-select and the edit form are enough.

**Grouping is purely organisational.** It never touches a connection. Live
sessions, tabs, tunnels, the files pane and the monitor are unaffected by
moving, renaming or dissolving a group; a tab is still titled with the host's
label. Upgrading changes nothing visible: every existing host starts
ungrouped and the list looks exactly as before until the first group is made.

## Sidebar

```
Hosts                       «
[ ⌕ Search hosts…          ✕ ]
▾ prod                 4 · 2 online
    web-01
    web-02 …
▾ test                     2
▸ home                 1 · 1 online     (collapsed)
  Ungrouped                2
    cache-01 …
[ ＋ New connection ]
```

- **Group header** shows `total · online` — the online figure is the number of
  members with a live session (`hostIsConnected`), so you can see at a glance
  which group has machines connected. Click to collapse / expand.
- **Order**: groups alphabetically (locale-aware, so Chinese names sort
  sensibly), each group's hosts in their existing `sort_order`. The ungrouped
  hosts come last, under an "Ungrouped" label that appears only when at least
  one group exists. With no groups at all there are no headers and the list is
  the flat list it was.
- **Collapsed state** persists across launches (localStorage, keyed by group
  name). A group that no longer exists is simply ignored.

## Search

A permanently visible box at the top of the sidebar, filtering as you type.

- Matches **label, address, username and group name**, case-insensitive
  substring. A group-name hit shows that whole group.
- While a query is active, groups with a match **auto-expand** regardless of
  their collapsed state and show only the matching hosts; groups with no match
  are hidden. Matched characters are highlighted. The header count turns into
  `shown / total`.
- **Esc** clears the box. **Enter** connects the first visible match — the
  same action as clicking it. No match shows an empty-state line, and Enter
  then does nothing.
- While a query is active each row also shows a dim `user@address` line, so a
  hit on the address or username explains itself. With no query the rows are
  exactly as before — the mockup draws that line permanently; the shipped
  sidebar does not, to leave row height alone.
- The global **Ctrl+K** command palette is untouched; it already searches hosts
  across the whole app and stays the keyboard-first route.

## Putting hosts into groups

Four routes, all writing the same `group_name`:

1. **Edit / new-connection form** — a "Group" field with a combobox of existing
   groups; typing a new name creates it. The hint under the field says whether
   the entry will "join an existing group" or "create a new group". Empty means
   ungrouped. A connect-only (unsaved) connection has no group.
2. **Right-click a host** → "Move to group" → an existing group, "New group…",
   or "Remove from group".
3. **Ctrl/Shift-select several hosts** → a bar at the foot of the sidebar offers
   "Move N to group ▾" with the same choices. It sits beside the existing
   batch-delete control, which is unchanged.
4. **Right-click a group header** → "Rename group" or "Dissolve group" (members
   become ungrouped; **no host is deleted**). Rename and "New group…" share one
   small name dialog (Cancel left, primary right, per the dialog convention)
   rather than the inline edit the mockup draws: it is easier to make robust
   and reuses the same control for both. Typing an existing name joins that
   group — for a rename, that merges the two — and the dialog says which.

Rename and dissolve are done as one `update_host` per member — no new IPC
command. The sequence is not atomic; a failure part-way leaves some members on
the old name, which is visible and retryable, and was judged not worth a
dedicated transactional command for a handful of rows.

## Multi-select under grouping

The existing selection logic addresses rows by **index into the visible
order**. With groups and a filter, "visible order" has to be the flattened list
of hosts actually on screen — headers excluded, collapsed groups' members
excluded, filtered-out hosts excluded. If it were the raw host list, a
Shift-click range would sweep in hosts the user cannot see and a batch delete
would remove them. So the sidebar derives one ordered list of visible host ids
and feeds that to the selection code; collapsing a group or typing a query
prunes anything no longer visible from the selection.

## Data and compatibility

- **Store**: `hosts.group_name TEXT` NULL, added by the usual idempotent
  `pragma_table_info` migration (not `schema.sql`, like every column since the
  first). Names are trimmed on write; a blank name means ungrouped.
- **IPC**: `save_host` takes `group_name?: string | null`; `update_host` takes
  it three-state — absent leaves it, `null` ungroups, a string moves — the same
  shape as `notes` and `key_path`.
- **Config bundle**: `BundleHost.groupName`, `#[serde(default)]`, so bundles
  written before this still import (as ungrouped) and a bundle carrying groups
  round-trips them. The format version is not bumped: old shellx simply ignores
  the unknown field.
- **SSH config import** produces ungrouped hosts; `~/.ssh/config` has no
  concept to map to.

## Deviations from the mockup

The mockup is the visual reference, not a pixel spec. Two intentional
differences in what shipped: rename uses a dialog instead of inline editing,
and the `user@address` line appears only while searching (both described
above). The footer batch control is a "Move N" button beside "Delete N" that
opens the same menu as right-click, rather than a full-width bar.

## Frontend structure

A pure module, `src/state/hostGroups.ts`, owns everything testable without a
DOM: deriving the group list, matching a host against a query, and building the
view — an ordered list of group headers and host rows plus the flat list of
visible host ids. `Drawer` renders that view; it holds the query and the
collapsed set and no grouping logic of its own.

## Testing

- Rust: group round-trip and trimming; update's set / change / leave / clear;
  bundle carries the group and an old bundle without the field still imports.
- Vitest: `hostGroups` (ordering, ungrouped-last, no-groups-means-flat, query
  matching across all four fields, auto-expand, visible-ids excluding collapsed
  and filtered hosts); the sidebar (collapse, search filters and Enter, batch
  move, rename / dissolve); the host form's group field.

## Not in this change

Tags; nested groups; drag-and-drop; persisting an explicit group order; a
per-group colour or icon; "connect to all in group". Each is separable and can
be added without reworking the above.
