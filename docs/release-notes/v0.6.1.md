## Transfer strip polish

- **Group cancel actually stops mid-enumeration.** A 2 500-file directory upload used to keep spawning new child transfers for a couple of seconds after the `✕` click — the JS-side per-child loop couldn't cancel spawns Rust hadn't dispatched yet. New Rust IPC `transfer_cancel_group` marks the group in a `cancelled_groups: HashSet` that `sftp_upload_dir` / `sftp_download_dir`'s enumeration loop checks per iteration. Frontend also tracks `cancelledGroupIds` locally so late `transfer:started` events don't bump the file counter.
- **Compact strip hugs the bottom.** Collapsed state is a flush 36 px header row with no divider handle. First group-expand snaps to the persisted `transferStripHeight`; a 6 px `row-resize` divider appears, drag it freely from there. Height carries across the two file browsers (RailFilesView ↔ FileBrowserView).
- **Shared strip component.** New `TransferStripSection` — both RailFilesView (the dual-pane Files view) and FileBrowserView (the standalone Hosts > Files view) render the exact same strip logic; a user's dragged height and expand toggles apply everywhere.
- **Sticky group header.** Scrolling a long expanded child list keeps the group's ProgressRow pinned at the top with the bytes-done / pause / cancel buttons still reachable.
- **Windows-narrow scrollbar.** New scoped `.shellx-transfer-scroll` class — 6 px thumb (down from the app-wide 10 px) with no gutter when the strip is compact.

## Responsiveness

- **Cancel truly stops now** — `write_all` was already inside a `tokio::select!`, but pause / cancel felt sluggish because the JS side only flipped state after Rust echoed a `transfer:done`. Optimistic UI: clicking pause / resume / cancel / group-cancel updates the local store immediately, then fires the Rust IPC. `applyProgress` freezes bytes while state is `paused` or `cancelled` so a trailing progress tick doesn't keep the bar advancing.
- **`queued → active` promotion.** `applyProgress` auto-promotes the state on the first byte tick — Rust's `mark_active` only mutated the in-memory map, so previously the frontend showed "queued" for the entire transfer.
- **Memoised `ChildRow`.** Expanded groups with hundreds of files no longer re-render every child row on every 100 ms progress tick.
- **Refresh debouncing.** `onTransferDone` coalesces reloads across a burst of child completions with a 300 ms debounce; a 30-file directory now triggers ONE reload instead of thirty. The debounce also fans out to `useFilesStore.perConnection` so Hosts > Files refreshes after uploads without a manual click.

## Files pane

- **OS drop-target outline** on Hosts > Files — the purple dashed accent border that Local / Remote panes already had.
- **Delete errors surface an alert** on RemotePane instead of silently no-op'ing on a permission denied / stat-failure remote path.
- **`..` row no longer flashes on drag** — disabled rows skip hover state, so the parent-nav pseudo-entry doesn't blink its background as the drag cursor transits it.
- **Recursive delete for freshly-uploaded folders** — new `sftp_remove_dir_recursive` IPC. RemotePane's Delete uses it for directory rows; the old single-file `sftp_remove_dir` only accepted empty directories.

## Hosts

- **Double-click opens a second shell** on a host row that already has an active session — `handleConnectSavedHost(host, forceNew=true)` bypasses the single-click dedup. Single click still switches to the existing tab (debounced ~250 ms so double-click can cancel the single-click action).
