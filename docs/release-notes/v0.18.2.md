# v0.18.2 — tunnel restart and stale-transport handling

Re-opening a tunnel that is already running now hands the local port over cleanly instead of leaving the auto-reconnect loop to sort it out, and an existing SSH transport is only reused after it answers a liveness probe. Reconnects settle on their own.

- **Re-opening a running rule is safe** — a second Play on an active tunnel, or an autostart racing a manual start, retires the previous forwarder silently and waits for the local port to be released before rebinding. Auto-reconnect stays out of it.
- **Dead transports are replaced, not reused** — before riding a host's existing SSH session, shellx probes it. A session whose transport died while the machine slept is closed and redialled, so a tunnel that reads "Running" is actually carrying traffic.
- **Exclusive local ports on Windows** — a local forward no longer shares its port with a second listener. A port that is genuinely taken fails with a clear bind error.
