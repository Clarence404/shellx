# v0.18.0 — structured logs + tunnel auto-reconnect

Tunnels now heal themselves. When an open forward drops (transport dead, remote sshd hiccup, laptop wakes from sleep on a new network), shellx retries with 2s → 5s → 15s → 60s backoff until it's back up. A new Logs panel in Settings shows exactly what happened at each step — every subsystem now emits structured events into a shared ring buffer and a daily-rotated jsonl file at `~/.shellx/logs/`.

- **Auto-reconnect** — every tunnel rule has an "Auto reconnect" toggle (default on) in its edit drawer. Unexpected close → yellow "Reconnecting…" pill with an "Attempt #N failed · next in Xs" countdown; success restores the green Active state. Authentication failures short-circuit with a "Credentials revoked" pill and a manual retry button so shellx doesn't lock you out.
- **Autostart on app launch** — a second toggle per rule. Marks the tunnel to open in the background the moment shellx starts, via a silent SSH transport if the host isn't otherwise connected.
- **Logs panel** — Settings → Logs shows every event: time, level, category, structured fields. Search across message + fields, filter by minimum level and category, flip Live on to stream new entries as they arrive, and click any row to expand full JSON. Export a jsonl dump of the current filter for bug reports.
- **Persistent logs** — one file per day at `~/.shellx/logs/YYYY-MM-DD.jsonl`, capped at 7 days. Sensitive fields (passwords, passphrases, key material) are never written. Disable disk writes from the panel if you'd rather keep everything in RAM.
