## Highlights

- **Directory transfers.** New Rust IPC family — `sftp_upload_dir` / `sftp_download_dir` — walks the source tree, mkdirs the destination parents-first, then spawns one per-file transfer per leaf. All children of the same directory transfer share a `group_id` so the frontend can render them as one aggregate row.
- **Pause / resume.** Every in-flight transfer (or an entire directory group) can be paused mid-stream and resumed. Backed by a shared `pause_flag: Arc<AtomicBool>` the byte-pumping loop polls on a short cadence; a new `transfer:state` event flips the UI immediately so paused rows don't wait on a progress tick.
- **Cancel actually stops.** `write_all` (and the download-side `read`) are now wrapped in `tokio::select!` alongside `cancel_rx`. Previously the select only checked cancel between chunks, so a stalled SFTP write could swallow the signal indefinitely. Cancel of a paused transfer also flips the pause flag off so the loop unparks and observes the cancel.
- **Grouped bottom-strip TransferQueue.** A 30-file directory upload now renders as ONE row (`↑ 📁 project/  4/30 files  12/240 MB · 5%`) with a full-width row-background progress fill, not thirty individual rows. Click the chevron to expand — child rows appear underneath with their own individual fills. Bulk pause / resume / cancel on the group operates on every child at once.
- **Recursive directory removal.** New `sftp_remove_dir_recursive` IPC — walks the tree, removes files, then dirs bottom-up. RemotePane's Delete now uses it for directory rows, so a freshly-uploaded folder can be deleted without the pre-v0.6 "RMDIR requires an empty directory" error.

## Under the hood

- **`SessionManager` refactor.** The inner map went from `HashMap<Id, LiveConnection>` to `HashMap<Id, Arc<Mutex<LiveConnection>>>`. The earlier "take out of map → op → put back" pattern raced under concurrent SFTP operations (concurrent `sftp_open_write` calls on the same connection would find the map temporarily empty and error with `Closed`). Ten-way directory transfers made this bug visible; the per-connection mutex fixes it and lets the outer map lock be held only for lookup / insert / remove.
- **`TransferInfo` schema.** New optional `groupId` field (`camelCase` on the wire; the rest of the struct stays `snake_case` to match the existing frontend type). Standalone transfers leave it `null`.
- **`TransferState::Paused`.** New variant alongside `queued / active / done / cancelled / failed`.
- **`transfer:state` event.** Emitted whenever a transfer's state flips independent of a progress tick (currently pause / resume). Frontend `useTransfersStore.applyState` handles it.
- **Queued-forever bug fixed.** Rust's `mark_active` only mutated the in-memory info map; the frontend never saw the state transition. `applyProgress` now promotes `queued → active` on the first byte tick.

## Frontend

- **`ProgressRow`** — new shared row component with a full-width background fill (accent purple → amber when paused → red when failed). Both group headers and solo transfer rows use it.
- **Directory drag.** LocalPane / RemotePane pointer drag now allows `kind === "directory"`; the drop handler dispatches to the recursive IPC based on the drag kind.
- **Directory download from file rows.** Right-click a remote directory → Download; the picker asks for a destination folder instead of a file save target.
- **Send to remote for folders.** LocalPane's row context menu offers Send to remote for directories, routed to `sftp_upload_dir`.
- **Bottom strip caps.** The whole TransferQueue is capped at `max-height: 36 vh` with internal scroll; expanded children lists cap at 200 px. A 500-file directory transfer can no longer push everything else off screen.
- **Cancel / pause / resume buttons.** Every row header has `⏸ / ▶` (context-dependent) and `✕`, sized and padded for a comfortable hit target.
